# Current portfolio

The portfolio follows Foldfolio’s complete device journey: the phone opens on native document scroll, remains pinned while the content moves inside its screen, and closes into a contact screen at the end. A fixed Home/Work/Archive/About/Contact dock stays inside the open device. Basic, Glow and pointer-driven Orbit modes plus Silver/Graphite/Copper/Sage finishes change the device appearance. Original technical artwork replaces human portraits. The page remains black and white apart from real project screenshot content and optional hardware finishes.

The homepage contains exactly five featured projects, with descriptions before screenshots. The remaining thirteen live at `/archive` as real interactive glass folders with project names and descriptions on their fronts. Opening reveals case, demo (when available) and source links. Keyboard Enter/Space opens, Tab reaches files, Escape closes. Filtering keeps live demos and research discoverable. All eighteen case routes share the open phone frame and preserve the original engineering evidence. Case descriptions precede their image as well.

The supplied 21st.dev Glassmorphism Folder Cards component is adapted under MIT; attribution is in THIRD_PARTY_NOTICES.md. React, TypeScript and Tailwind already existed, so no shadcn bootstrap or new dependency was needed; reusable supplied UI lives in components/ui. The portfolio uses existing React hooks and native CSS3D, with one requestAnimationFrame callback for scroll. The content width stays fixed while hardware unfolds to prevent reflow changing scroll endpoints. Hidden faces are inert. Reduced-motion visitors skip opening/closing and pointer tilt; without JavaScript the content is a normal document with all case links available.

The contact form validates name/email/message and opens a prefilled draft in the visitor’s email application. The site does not send, receive or store form submissions; there is no backend form service. Plain email/GitHub/LinkedIn links remain available.

All 18 projects remain accessible. The five featured entries and the archive are an editorial ranking of implemented engineering scope (service integration, concurrency/recovery, independent evaluation), not a score or externally validated difficulty measure. Breakroom, Signalworks and Pair Bench lead; unreplicated research archives appear last. Every case preserves source links, verification and limitations separately from its plain-language introduction.

Verification: `npm run type-check`, `npm run lint`, `npm run build`; the full browser suite is delivery/check-phone-fold.mjs in the parent workspace (desktop1440px/mobile390px/320px, framed scrolling, hinge endpoints, dock, modes, folders, form validation, reduced motion/no-JS and18case routes). No model inference occurs on the portfolio itself. Earlier phase2 documentation describes the previous interface and historical model experiments.

Nine preview images are actual browser captures of the working project interfaces (public/previews), not fabricated mockups. They load lazily and use unoptimized local image files so no image-processing service is required. Original technical SVGs remain for the hero and source-only projects. Case descriptions now match football training/queries, travel report/reading examples, actual Steam counts, recorded coding attempts and their separate local backends.

The main tasks need no downloaded AI model. Current and Neon train small models directly in the browser. Pair Bench and Answer Key can replay actual prior model outputs and run independent checks. Free cloud-generation adapters are deployed but remain disabled without an explicitly confirmed free provider connection. No API keys, paid plan, billing or fallback were configured. Free provider quotas are limited; unlimited free cloud LLM training or serving is not claimed.
